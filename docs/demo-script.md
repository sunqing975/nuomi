# 糯米杀手级 Demo 脚本

> 一场 5 分钟的「全能闭环」演示：给糯米一个真实任务，它自己完成 **调研 → 记忆 → 知识 → 执行 → 产物** 全链路。
> 配套文档：`docs/placeholder-priorities.md`（P0 项做完后再排演本脚本）。

## 0. 为什么是这个 demo

- **一句话卖点**：给糯米一个真实任务，它自己完成「调研 → 记忆 → 知识 → 执行 → 产物」闭环。
- **覆盖能力层**：
  - UI 层：SSE 逐字流式 + 深度思考折叠块 + 工具调用卡片
  - 能力层：web 抓取 / 知识库 RAG / 记忆双通道
  - 执行层（Phase 5 核心）：fs 文件工具 / shell 沙箱
  - 持久化：跨会话记忆回放 / 工作区真实落盘
- **面试官视角**：不展示 20 个插件的广度，而是让一个任务里 6+ 个能力自然协作——记住一个 wow 时刻，胜过一张功能清单。

## 1. 前置条件（5 分钟）

- `make start` 拉起桌面版（release 打包后直接用打包版，见 P0-1）。
- 模型：设置里激活 DeepSeek（工具调用可靠）。
- 插件全开（默认配置即可）。
- 工作区干净：`~/Documents/Nuomi` 清掉演示残留报告。
- 网络正常；准备降级方案（见 §7）。
- **正式演示前必须实跑一遍全流程**，记录真实工具调用顺序（模型有随机性）。

## 2. 时间盒

| 段落 | 时长 | 内容 |
|---|---|---|
| 开场 | 30s | 一句话卖点 |
| Step 1 布置任务 | 90s | 调研 + 记忆 + 报告落盘 |
| Step 2 追问知识库 | 45s | RAG 语义检索 |
| Step 3 跨会话记忆 | 45s | 全新会话想起你 |
| Step 4 产物回看 + 执行 | 60s | 文件面板 + shell 统计 |
| 收尾 | 30s | 数据总结 |

核心版 5 分钟（Step 1–4）；完整版 8 分钟（Step 4 加 shell 统计动作）。

## 3. 分步脚本

### Step 1 布置任务（90s）

**用户输入（可复制）**：
> 我在准备 AI 编程工具的产品面试。帮我调研 Cursor、Claude Code、DeepSeek Harness 三个产品，对比它们的核心差异，写一份 markdown 报告存到我的工作区。顺便记住我在准备这场面试。

**预期行为**：
- 回复流开始，深度思考折叠块展开；
- 工具卡片依次出现：`web http_get`（或搜索）→ `memory_write` → `knowledge add` → `fs write_file`；
- 完成时，侧栏文件面板出现报告文件。

**讲解话术**：
> 注意看：模型在深度思考，然后自己决定调用顺序——web 抓取、记忆、知识库、文件系统，全是插件。它刚把报告写进了真实工作区，这是 fs 插件，带路径防穿越。

**UI 展示点**：推理折叠块 / 工具卡片流 / SSE 逐字流式。

**失败降级**：web 抓取失败 → 提前备好两段资料文本，改为「基于以下资料完成」；仍失败 → 跳过 web，只演示记忆 + 知识 + fs。

### Step 2 追问知识库（45s）

**用户输入**：
> 刚才的调研里，Harness 的插件机制和 Cursor 的 agent 模式，核心差异是什么？

**预期行为**：从知识库 RAG 语义检索，给出有依据的回答（不编造）。

**讲解话术**：
> 这个问题没有直接问上下文——糯米是从知识库语义检索到的。存进去的是整段资料，问的是另一句话，靠 embedding 找到相关段落。词法检索兜底可插拔，换 RAG 方案 = 换插件。

**失败降级**：检索不准 → 改问「插件机制分几级加载」（与存入内容字面更接近）。

### Step 3 跨会话记忆（45s）

**操作**：点侧栏「＋ 新会话」（或 `/new`），输入：
> 你还记得我在准备什么吗？

**预期行为**：答出「AI 编程工具的产品面试」——跨会话记忆回放。

**讲解话术**：
> 注意这是全新会话。它记得你，靠的是记忆双通道——刚才模型主动写了一条（memory 插件），现在系统每轮按用户消息检索记忆注入 prompt。跨会话能想起，是记忆层的看家功能。

**失败降级**：没答出 → 引导「想想我让你记住的事」；仍失败 → 切回旧会话演示会话内记忆。

### Step 4 产物回看 + 执行能力（60s）

**操作**：切侧栏「文件」面板，展开工作区树 → 打开报告文件；然后输入：
> 再帮我统计一下报告里三个产品各出现多少次，追加到报告末尾。

**预期行为**：`shell` 命令执行（grep/wc）→ `fs` 追加写回 → 报告末尾出现统计行。

**讲解话术**：
> 文件面板就是真实工作区。它刚用 shell 跑统计、用 fs 追加写回——执行能力分三级沙箱：只读 / 工作区写 / 全访问；写命令有黑名单、路径防穿越，高风险命令进审批门（human-in-the-loop）。

**UI 展示点**：文件树 / 文件内容 / shell 工具卡片 / 权限提示（若触发审批）。

**失败降级**：shell 统计失败 → 直接展示文件内容 + 讲沙箱架构（跳过统计）。

### 收尾（30s）

**话术**：
> 刚才 5 分钟，糯米完成了一次真实调研：调用 5 类工具、跨 2 个会话、落下 2 个文件、记住 1 条你的信息。这一切的核心是——打字，其余全是插件。

## 4. 面试官可能追问 & 应答要点

| 追问 | 应答要点 |
|---|---|
| 这和 Claude Code 有什么区别 | 定位不同：Claude Code 是终端里的冷工具；糯米是有记忆、有人格的桌面助手，扩展体系是 v0.7 三区：插件=可选能力（加目录=加能力）、模块=内核组成部分（服务/钩子/Agent preset）、技能=独立文档资产 |
| 插件体系怎么设计的 | v0.7 三区：插件（plugins/，可选能力）/ 模块（modules/，内核）/ 技能（skills/，独立文档资产），目录即分类；加载按三级：元数据常驻 → 指令触发 → 资源按需。「轻的常驻，重的能拖就拖」 |
| 记忆怎么实现的 | 双通道：模型主动写（memory 插件）+ 系统被动注入（每轮检索，会话内冻结快照保 prefix cache）；Provider 化，可换 Mem0 |
| 执行安全怎么做 | 三级沙箱 + 写命令黑名单 + 路径防穿越 + 高风险工具审批门（human-in-the-loop） |
| 上下文无限增长怎么办 | `awrap_model_call` 直接构造模型输入，旧消息压摘要、token 有界（实测 21→4）——讲真实踩坑（add_messages 合并会还原裁剪） |
| 为什么不做多用户 | 桌面单用户工具（Obsidian / Raycast 思路），复杂度换不来收益——2026-10-02 主动砍掉多用户 / JWT / PostgreSQL |
